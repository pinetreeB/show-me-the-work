## 무엇이 문제였나 (쉬운 말)

**폴더 이름을 대면 감시가 통째로 뚫렸습니다.**

```
rm shared-dir/peer.py   → 막힘     (파일을 직접 대면)
rm -r shared-dir        → 통과     (상위 폴더를 대면)
```

남의 작업 파일이 폴더 안에 있을 때, 파일 대신 **폴더를 지목하면** 게이트가 비껴갔습니다. 폴더째
지우는 게 파일 하나보다 피해가 훨씬 큰데도요. `rm`·`Remove-Item`·`mv`·`git checkout`·`git rm` 전부
해당했고, **처음부터 있던 구멍**입니다. 세 라운드 검증에서 아무도 못 찾았습니다 — 다들 파일 하나를
대상으로만 시험했기 때문입니다.

윈도우 문법(`rd /s`)도 따로 뚫려 있었습니다. 이건 수리 후 검증에서 잡았습니다.

## 오탐(억울한 차단)도 함께 고쳤습니다

감시가 정상 작업을 막기 시작하면 도구를 꺼버리게 되고, **꺼진 감시는 아무것도 못 막습니다.**
그래서 오탐을 미탐보다 우선했습니다.

- `perl -Ilib` — 라이브러리 경로 지정인데 제자리편집으로 오인
- `sc stop <서비스>` — 윈도우 서비스 제어인데 `Set-Content` 줄임말로 오인
- `git rm --dry-run` — 아무것도 안 지우는 예행연습인데 차단
- `Remove-Item -WhatIf` — 다른 명령은 인정하는데 이것만 누락

마지막 검증 라운드에서 **신규 오탐 0건**을 확인했습니다. `shared-dir2` 같은 이름만 비슷한 폴더,
